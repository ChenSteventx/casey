# Casey 最小权限说明

Casey 按最小权限运行。安装系统前置和日常使用是两件事：Git、Node.js 若尚未安装，组织的软件安装策略可能要求一次管理员批准；Casey 本体、账户配置、MCP、浏览器回放和报告生成都应使用普通用户，不需要管理员、Docker Desktop 或全盘访问。

## Codex / Claude Code / 通用 agent 必需能力

| 能力 | 用途 | 不具备时怎么办 |
|---|---|---|
| 读写并删除 Casey 仓库内文件 | 安装依赖、生成本地 case/run、清理测试实体的本地记录 | 只授权当前用户拥有的 Casey 目录；不要授权整盘 |
| 执行 Node.js、npm 与本地脚本 | 运行安装检验、MCP、编译、回放和报告 | 仅放行仓内入口；禁止任意远程脚本求值 |
| 写当前用户的 agent 配置 | 安装 skill/plugin 与合并 Casey MCP | 只授权当前用户配置文件，保留既有配置 |
| 启动 Playwright Chromium | web 示教、正式回放、录屏 | 沙箱不允许启动浏览器时，转到本机交互会话 |
| 访问 `127.0.0.1` 并监听用户端口 | MCP、CDP 与需要时的本地适配器 | 只放行回环；不得把 CDP 暴露到局域网或公网 |
| 访问批准的网络目标 | 下载 GitHub/npm/Playwright 依赖，以及正式测试时访问真实 SUT | 缺网络时停止；绝不退化到 fake-SUT |
| 本机隐藏输入 | 配置账户且不把秘密放进聊天、argv 或日志 | agent 无隐藏输入时，让用户在本机终端完成该一步 |

Windows 原生的仓库必须位于当前用户拥有的本地目录，不能放在 `Program Files`、多人共享目录或公共同步盘。账户 ACL 收紧只操作当前用户自己的 `.auth/` 和账户文件；失败时应移动仓库，不应要求管理员接管目录。

## 只在特定任务需要的权限

- 正式 web 测试：Casey 的 Node.js + Chromium 实际执行面必须能访问真实 SUT。当前公开版的正式 web CLI 仍要求回环 endpoint；远端真站需要本地适配器，真实 SUT 已在回环时不需要额外代理。
- Windows 原生 web：使用本机 Node.js 与 Chromium，不使用 Docker。现有本地适配器也是普通用户进程。
- WSL2：只有 WSL 本身不能访问真站、而 Windows VPN/企业网络可以访问时，才需要 Windows ↔ WSL 反向隧道。
- 医生站 / Hi 小助 CEF：agent 必须和应用位于同一 Windows 交互式桌面会话，并获准附着本机回环 CDP；不需要管理员，但需要人工确认专用测试账户且没有真实患者数据。
- 修改源码并推 GitHub：额外需要 git 写权限和用户自己的 GitHub 凭据；普通测试操作不需要 GitHub 写权限。

## 明确禁止索要的权限

- 不得要求为 Casey 启用管理员常驻、关闭 UAC、永久放宽 PowerShell 执行策略或接管非当前用户目录。
- 不得要求 Docker daemon、Docker Desktop、WSL2 或远程桌面作为 Windows 原生的默认前置。
- 不得索要整盘读写、任意站点网络权限、明文账户、Cookie、token 或真实目标地址到聊天窗口。
- 不得因为权限不足而启动 fake-SUT、跳过人签、关闭录屏或把机械回放包装成 PASS。

agent 在开始前应逐项报告“具备 / 缺失 / 仅本任务需要”。缺一项时只申请该项；无法取得时输出明确缺口并停止相关阶段，不能自行提权或静默绕过。
