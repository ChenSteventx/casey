# Casey 使用说明与能力边界

推荐入口是 `skill`：用户只描述测试目标、前置条件、操作和期望，代理负责环境检查、生命周期命令与产物路径。只有用户明确要求命令时才暴露 `CLI` 细节。

## 通过自然语言测试 AI 中台

已有已签用例时，可以直接说：

> 在真实 AI 中台跑历史版本用例。必须联网走真实环境，生成每个用例一份独立 HTML，包含自然语言用例、原子操作、同次录屏和附件；再给我四态摘要。

代理应先检查本机、凭据、回环代理与两段真实 HTTP 连通证据，然后只在真实目标上回放。正式结论来自零 `LLM` 的确定性裁定；视觉复核只能写 `CONSISTENT`、`INCONSISTENT` 或 `INDETERMINATE` 摘要，固定 `verdictImpact=none`，不能修改四态裁定。

正式交付分两段：第一段真实 `run` 先产录像、四态裁定、待视觉报告和同 run 摘要绑定，并固定以“未正式完成”结束；代理实际观看这次录像后，第二段 `finalize-run` 在零 SUT、零 replay 下校验录像 / 裁定 / 输入摘要与视觉证据，重建同一份报告。只有四态全 PASS、录像完整且视觉为 `CONSISTENT` 才输出 `FORMAL_DELIVERY GREEN`。这避免在录像尚未产生时预先写“视觉通过”。

新自然语言用例不能直接跳过签署。当前链路是：候选归一 → 流程映射 → 真机编译与观测 → 断言草拟 → 人签 → 确定性回放 → 裁定 → 报告。人签之前不允许正式回放。

每个测试用例的正式交付是一个独立 HTML，至少含：

1. 已签用例的自然语言描述；
2. 分解后的动作和断言原子；
3. 同次真实回放录屏；
4. HTML、Markdown、JSON、裁定、三轴、回放历史、运行指标与视频元数据等附件。

聚合 HTML 只是索引，不能替代单用例正文。

## 自动化失败后转人工示教

可对代理说：

> 这个流程自动编译失败了。不要猜定位，转人工示教；打开真实环境让我操作，采集后入账并蒸馏，但不要代签，也不要把采集包当成回放成功。

当前 web 示教链已经有三个命令能力：

1. `record` 在 Playwright Chromium 中打开真实 web 页面，采集点击、双击、输入、回车和导航事件；
2. `intake` 做凭据与包完整性复核并写追加式台账；
3. `distill` 生成带溯源的候选 `TestCase` 与 mapping。

必须实事求是地区分“可采集”和“可回放”：

- 示教录制包固定为 `signed:false`、`replayReady:false`、`distillRequired:true`；它不是录屏报告，也不是正式事件规格。
- 当前 `distill` v1 把所有步骤标成 `pending`，不会自动把裸点击反解成已验证原子。
- 蒸馏后仍须由 `LLM` 在 `CLI` 外归一，再经过 `ingest`、`flow-bridge`、真机 `compile`、`draft` 和人签，之后才有资格回放。
- `skill` 已固化失败分流：真实网络与安全会话成立时，无法映射的原子或已确证 `HARNESS_ERROR` 转人工示教；环境 / 代理 / 登录失败先修环境，`SUT_DEFECT` 保留缺陷结论，歧义或有破坏风险时等人确认。它是代理编排规则，不是裁判逻辑，也不会把失败自动吞成录制成功。
- 这条“人录 → 正式回放”全链还没有同一次医生站 / Hi 小助真机验收证据，不能声称已经成功。

## 医生站与 Hi 小助

本版本把普通 web 与 CEF 分成两个真实通道。对医生站 + Hi 小助的事实状态是：

- web/Chromium 页面可以进入示教采集链；
- `cef-record` 可经回环 CDP 附着唯一真实 CEF page target，以 F8 收口示教并保存逐帧 screencast；`cef-replay` 只消费已入账且哈希未变的 capture，产机械动作收据、可播放录屏和独立单例 HTML；
- CEF 机械收据固定 `formalVerdictEligible=false`，不含已签断言和标准三轴，因此不能冒充正式 PASS；当前录屏是逐帧 JPEG + 播放 HTML，不是 MP4/WebM；
- 医生站容器类型尚需真实环境只读确认；
- 当前只支持单一 CEF page target；原生控件、跨窗口和 CEF/原生混合流程尚不支持；
- 两者统一的“手动录制 → 入账 → 蒸馏 → 人签 → 回放 → 录屏报告”尚未完成真机闭环，所以这里只能称“已开发、待真机验收”。

可增加 `LLM` 视觉辅助来解释截图、提出候选动作或做报告复核，但必须置于确定性裁定之外。视觉信息不足时应转 `NEEDS_HUMAN`，不能凭视觉印象发 `PASS`。

## 自学习与进化

当前已经实现受控的“成功示教 → 候选学习原子”，但不会自动污染正式注册表：

- 示教蒸馏保留事件溯源，但 v1 全部 `pending`；
- `atom-propose` 只有在 intake 同哈希、已签 expected、标准真实 `axes` / `verdict` 全 PASS、唯一身份回读、录屏与同 run provenance 都齐全时才产 pending 候选；CEF 的非正式机械收据明确不够资格；
- `atom-sign` 绑定候选哈希，`atom-promote` 是第二次显式晋升决定；晋升后宏原子可被 flow bridge / compile 确定性展开，并拒绝内置原子冲突、重复定义、缺参和嵌套学习宏；
- 当前学习注册表仍为空，因为仓内还没有一组“同一次已入账示教 + 正式真实 PASS + 录屏”的完整现场样本；因此不能声称已经自学习出可复用原子；
- 自愈只允许处理已确证的 `HARNESS_ERROR`，而 `casey heal` 当前仍是 exit 3 的诚实桩；
- 动作词汇表和通道驱动的新增需要 schema、驱动、三轴证据、真实回放和人签，不允许从一次坐标点击直接升格。

当前实现的是“人定义候选宏 + 证据自动核验 + 两次显式人决策 + 可复用展开”，不是自动聚类或无需监督的模型训练。证据绑定采用本地 SHA-256 与同 run 元数据；它是本机可信链，不是远程签名证明。

## 三种入口的实际差异

| 入口 | 适用对象 | 当前事实 |
|---|---|---|
| `skill` | 自然语言使用者 | 最完整的用户入口，可编排 CLI 外 `LLM` 步骤；仍受人签和真机前置约束 |
| `MCP` | Claude Code / Codex 工具调用 | 已提供 16 个工具，含 CEF 示教与机械回放；`casey_run` 只完成真实产证第一段。当前没有 `finalize-run`、`casey_distill` 和原子候选三段式，所以代理须由 skill 内部转调 CLI 收口 |
| `CLI` | 代理内部与维护者 | 生命周期命令最全，含 `finalize-run`、`distill`、`atom-propose`、`atom-sign`、`atom-promote`；`heal` 未实现，退出码 3 必须如实上报 |

如果 `skill`、`MCP` 和 `CLI` 能力不一致，以实际命令和退出码为事实，不把文档愿景当成完成状态。
