# Casey 报告输出要求

面向现场测试报告。普通用户只给自然语言用例；代理内部负责回放、裁定、报告与清理。

## 必须项

1. 报告顶部必须包含「测试用例」区块，放在录像、结论、验收点、接口取证之前。
2. 「测试用例」内容必须是自然语言：优先使用用户原文；若从已签 TestCase 生成，必须由 intents 串成可读句子。
3. HTML、Markdown、JSON 三种产物都必须携带同一份自然语言文本；JSON 字段名为 `naturalLanguage`。
4. 报告顶部必须包含「原子操作」区块，紧跟「测试用例」。每条只包含一个可观察动作或一个断言，不得把多个动作合并成一条。
5. HTML、Markdown、JSON 三种产物都必须携带同一份原子操作清单；JSON 字段名为 `atomicSteps`。验收点、截图、网络取证或错误摘要必须能回指到原子操作编号。
6. HTML 报告必须包含业务步骤录像或明确的视频链接；录像不得包含登录账号、密码输入过程。
7. 报告必须包含四态结论：`PASS / SUT_DEFECT / HARNESS_ERROR / NEEDS_HUMAN`。
8. 报告必须包含关键验收点的期望与实际，不能只说“通过”。
9. 编辑型用例必须包含清理证据：删除前命中数、删除后命中数；必要时再按精确名称复查残留。
10. 任何未实现、未签署、未录制、未清理、证不出的部分都要明示，不能以文件存在或脚本退出作为通过结论。
11. 工作流类用例如果涉及发布、导出、历史版本或可运行状态，报告必须证明工作流不是空画布：至少包含开始节点、结束节点、二者连线、开始节点配置、结束节点配置。未满足时不能把该报告算作满足工作流验收。
12. 变量配置类用例如果未明确指定变量来源或变量归属，默认选择「自定义变量」，并在原子操作中显式写出该默认选择。

## 推荐首页顺序

1. 标题、caseId、工作流/实体名、执行时间。
2. 测试用例自然语言表述。
3. 原子操作清单。
4. 回放录像。
5. 裁定概览与四态计数。
6. 验收点清单。
7. 节点配置、接口取证、截图、原始 JSON。

## 登录录像

登录预备动作不进入录像。需要录像时，用未录制上下文完成登录，再把登录态转移到录制上下文；录制从业务动作开始。
