# 开发评审模型额度纪律

本页约束开发流程中的模型评审，不改变 Casey 运行时：`verdict.mjs` 始终零 `LLM`，真实测试完成标准也不因评审工具变化而放松。

## 默认评审顺序

1. 先由实现方运行与差异直接相关的静态检查、schema 检查和零 `SUT` 纯函数检查，并整理实际退出码。不得为凑证据运行 fake-SUT、夹具 `SUT` 或未审计整包 gate。
2. 再由 `pi.dev` 使用 `deepseek-v4-pro` high 做只读评审，输入仅含计划、基线到候选的差异、相关文件和测试证据。普通文档、安装脚本、非内核小修默认到此收口。
3. 只有裁判、签署、凭据门、fail-safe、冻结协议、强制层或真机高风险接缝，才在 `pi.dev` 已收敛后调用 Claude Code Fable high 做一次终审。用户明确指定其它评审者时从其指令。

## Claude Code 调用边界

- 同时最多一个 Claude Code 评审进程；不得让它自行派生 subagent。
- 首轮只读固定基线与候选提交之间的差异，不读无关历史，不做全仓搜索；全仓架构审必须由 Steven 单独批准。
- 评审包必须写明文件白名单、非目标、已跑证据、不得运行任何 `SUT`，并要求只输出 `Critical`、`High`、`Medium` 与最终结论。
- 单次调用设置有限时长。超时或额度不足即停止，不用相同材料连续重试；保留现有证据并标记未完成。
- 修复后复审只提供原 finding、处置说明和对应 hunks；不得重新提交整仓材料。
- Claude Code 只能评审，不能替代确定性测试、真机 UAT、人签或视觉复核。

## 降级与记录

Claude Code 额度不可用时，默认继续完成本地确定性验证和 `pi.dev` 只读评审。Steven 明确允许 `pi.dev` 代审时，以其结论收口并记录模型与 thinking 等级；没有该授权时，将 Claude Code 终审标成待补，不能把同族或未执行审查冒充完成。

每次评审记录至少包含基线、候选提交、评审文件集、模型、thinking 等级、耗时、结论、findings 处置和未覆盖项。模型长时间运行本身不构成更高质量证据。
