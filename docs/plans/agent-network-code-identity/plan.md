# `agent-network-code-identity` 实施计划

## 目标

新增闭集 `identityMode: 'network-code-dom-name-v1'`，让智能体身份链在 DOM 只有名称、编号只存在于完整网络信封时仍能安全定位；未声明模式继续执行现役 DOM 名称加编号双锚，旧摘要和 `identityProfileDigest` 字节不变。

## 实现面

1. 新建共享 `lib/agent-identity-profile.mjs`，单点解析智能体身份剖面、产账本通道与指纹。旧模式的指纹材料仍严格等于现役 `listApi`；新模式的指纹材料闭合覆盖模式、`listApi`、容器和名称选择器。
2. 扩展 `resolveDualIdentity`：新模式仍先过信封完整性与同名唯一门，再比网络编号、已签名称/编号/平台标识；DOM 只须精确名称，不读取编号。未知模式 fail-closed。
3. 扩展物理卡片门：新模式只在容器内按精确名称圈定单一卡片并返回固定 `ElementHandle`；点击前在同一句柄重验 `isConnected`、可见和名称。新模式若携 `cardFields.code` 直接拒绝。
4. 编译与回放共同消费共享剖面解析结果；两侧不再各自复制摘要算法。旧剖面行为与摘要字节不得变化。

## 验收点

- A1：旧剖面解析成功，通道投影与现役相同，指纹与现役算法逐字相同；未知模式、缺字段与新模式携 `cardFields.code` 均拒绝。
- A2：新模式的指纹受模式、网络通道、容器和名称选择器共同约束，任一变化都会改变指纹。
- A3：新模式中 DOM 名称唯一、完整信封同名唯一且网络行与已签三元组全等时返回 `unique`；信封多同名、DOM 多卡、签署编号或平台标识不等均拒绝。
- A4：新模式物理门只返回同一张卡片句柄；点击前节点被替换、隐藏或改名均零点击，合法同句柄才点击。旧模式仍要求名称加编号。
- A5：编译与回放源码均调用共享解析/指纹函数；旧的内联摘要实现消失。
- A6：既有 agent 身份零 SUT 金牌与主确定性自检保持绿色。

- `route:human`：修改真实用例剖面、冻结件与清单摘要需要 Steven 重签，不在本实现分支代签。
