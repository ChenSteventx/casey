# GRILL：智能体名称在 DOM、编号在网络信封的身份模式

## 决断

真实智能体卡片的副标题是描述，不是编号。现役双证门要求同一张卡片同时提供名称和编号，因而不能为该页面铸造有效身份观察。采用加法式闭集模式 `network-code-dom-name-v1`：

- DOM 只负责同一卡片内的精确唯一名称与待点击物理句柄；
- 网络信封负责完整集合、唯一同名行、编号和平台标识；
- 已签名称、编号、平台标识仍须与网络行逐项全等；
- 点击前须在已钉句柄上重验连接、可见与精确名称；
- 新模式禁止声明 `cardFields.code`，避免把描述误当编号；
- 未声明模式的旧剖面维持原行为和原 `identityProfileDigest` 字节。

## 不做

- 不修改冻结锁版本或签署格式；
- 不启动浏览器、隧道或被测系统；
- 不放宽网络信封完整性、同名歧义或已签三元组核对；
- 不改变旧模式的 DOM 名称加编号双锚语义。

## 停止条件

新模式纯函数、物理句柄门和编译/回放剖面解析接线全部由红先行金牌覆盖；旧模式判定输出、剖面摘要与指纹逐字保持；受影响的零 SUT 金牌与统一语言检查退出码为 0。真机选择器与最终用例重签仍由主线真机 UAT 承接。
