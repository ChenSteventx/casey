## Findings

### M1 · Medium · `lib/cred-gate.mjs:58`

**严重级**：Medium  
**位置**：`neutralizeDomainLineageKeys` 内  
`new RegExp(\`"${key}"(\\s*:\\s*)(null|"${LINEAGE_VALUE_SOURCE}")\`, 'g')`  
的 `null` 交替无词边界/后继终止。

**失败场景**：  
对原文 `"batchToken": nullable`（及 `nullish`、`nullfoobar` 等以 `null` 为前缀的非 JSON 垃圾值），正则吃掉前缀 `null` 并中和键名 → 扫描副本变为 `"<nc-lineage-key>": nullable…`。若后缀不含其它禁关键词，门返回 `ok:true`。  
按 plan §1 / GRILL §2：仅精确 `null` 或合形引号串可中和；值形状不符应**不中和**、因键内 `token` 子串照拦。

**本机实证**：

```
PASS | nullable            | ok   ← 偏松（契约应 BLOCK）
PASS | uniqueNameToken nullable | ok
BLOCK | Null capital       | token（大小写敏感，仍 fail-closed）
BLOCK | nullpassword       | password（后缀关键词仍拦）
```

**绕过评估（找绕过优先）**：  
不能借此把含 password/token/secret/… 的值或凭据字面量带出门（值/后缀仍全额扫；字面量扫原文）。扩大的是「键名 `batchToken`/`uniqueNameToken` 在 null 前缀畸形值下的误放行」，属中和面相对契约偏松一寸，不是「真凭据关键词假阴性」级漏洞。生产 `JSON.stringify` axes 走精确 `null`/引号串，G6 不受影响；门以原始文本扫描，畸形串仍在威胁面内。

**修复方向（评审不改码，仅建议）**：  
`null` 改为带终止的断言，例如 `null(?![A-Za-z0-9_])` 或 `null(?=\s|[,}\]]|$)`；并补 G2 同类钉（`nullable` 应仍拦 token）。

### ① 是否闭合 r1-M1

**是，已闭合。**

| 契约点 | r1-M1 | 24acd64 |
|--------|-------|---------|
| `null` 交替终止 | 无边界，吃前缀 `null…` | 负向先行 `(?![A-Za-z0-9_-])` |
| `"batchToken": nullable` 等 | 误放行（实证 PASS） | 不中和，仍拦 token |
| 精确 `null` / 合形引号串 | 应放行 | G1 仍绿；`null`/`,`/`}`/空白/EOF 终止均放行 |
| G2 回归钉 | 建议补 | 三 junk 入环，exit 0 |

负向字符类含 `-` 比 r1 建议的 `(?![A-Za-z0-9_])` 更贴契约：直接钉死 `null-garbage`（连字符续缀）不得吃前缀。精确 JSON `null` 后继（空白/`,`/`}`/`]`/EOF）均不在 `[A-Za-z0-9_-]` 内，放行面不缩。

本机探针（`credentialGate` 直调）：exact null / good string / ut exact null → PASS；nullable / nullish / null-garbage / nullfoobar / null_foo / ut nullable → BLOCK token；nullpassword → BLOCK password（后缀关键词仍先命中）。
