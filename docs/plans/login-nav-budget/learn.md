# learn · login-nav-budget

## 这轮学到什么

1. **一条链路上的骑线预算会连环暴露，修一个露一个**。B4 依次撞出 sleep 导入缺失 →
   入口锚定窗 4s → 登录导航预算 15s，三块都是「页面/环境变重后旧预算压线」一族。
   每修一块，链路推进到下一块的骑线点。启示：撞到第一块时就该问「同链路还有哪些
   预算贴着当年实测值」——本轮若在入口锚契约时顺手普查各超时常量与现役实测的
   余量比，登录这块可以少跑一轮真机失败。
2. **超时上限（天花板）与等待（sleep）是两类语义，评审判据也不同**：天花板改大对
   快路径零行为差，只需核「全部消费点都是上限选项」；等待改大是全路径加时。
   金牌对天花板要双向钉：慢载能过（预算容纳）+ 快载不拖（完成时刻在载入时刻附近、
   非预算满）。
3. **失败密封的边界在看门狗强退处**：pi 那条 Medium 指出 `process.exit(1)` 在
   loginBootstrap 中途触发时不落 compile-report.json——密封承诺只覆盖「函数正常
   返回失败」的路径，不覆盖「被看门狗击杀」。任何给成功路径稳定等待加宽的改动，
   都在把最坏时长推向看门狗，值得独立预算化（挂账为加固候选）。
4. **替身对超时语义的忠实复现是判别力来源**：goto 替身按 Playwright 语义
   （预算内 resolve、不足 reject）实现后，20s 载入天然构成 15/30 判别区间——
   不需要任何面向断言的特判。
