# 可信闭环自进化计划（full）

## 0. 目标与完成定义

本计划把 Casey 现有的「示教录制 → intake → distill 候选」和「裁定下游的有界自愈骨架」接成一条**可审计、可回滚、默认不自治**的学习闭环：

`真机示教/真实执行 → 身份观察 → 语义锁定 → 候选原子 → 真机复验 → 确定性裁定 → 人签晋升 → 后续复用 → 漂移监测/撤销`

只有同时满足下列条件，才可称为“可以放心使用的闭环自进化”：

1. 输入证据来自联网的真实 SUT；hermetic/fake-sut 只可做开发期单元与金牌验证，**不得充当功能完成或真机验收证据**。
2. LLM/视觉只负责提出候选、解释差异和辅助复核；`PASS`/`SUT_DEFECT` 仍只由零 LLM 的确定性裁判产生。
3. 任何拥有名称与编号/编码的业务对象，都以类型 + 名称 + 编号/编码联合锁定；同名、缺号、冲突或漂移一律 fail-closed。
4. 候选原子不得直接进入正式 registry；必须经过真实回放、证据完整性检查、确定性裁定和人工签署。
5. 晋升可追溯、可撤销；后续复用失败不会改写历史成功，也不会自动修改冻结断言、正式 spec 或 registry。
6. 每条真机验收用例独立生成一个 HTML，包含自然语言测试用例、分解后的原子操作、录屏和附件。

本计划与 P6 自愈严格分工：可信闭环自进化学习可复用的候选原子和对象绑定；自愈只在已确证 `HARNESS_ERROR` 后提出非就地漂移补丁。两者都不得反向污染 verdict。

## 1. 当前基线

- 已有：`record → intake → distill` 的安全登记和候选投影；v1 distill 全部 `route:human`，不会伪装成可回放原子。
- 已有：录屏、确定性 replay/verdict/report、失败记录与指纹等证据底座。
- 在制：对象身份观察旁车、语义锁定、录制后绑定与回放前复核。
- 未完成：成功录制/回放到正式原子 registry 的晋升链；真实 SUT 的跨运行复验；自动撤销/降级；可运行的 `casey heal`。

## 2. 阶段计划

### E0 · 安全边界与 schema 冻结

定义并冻结四类产物：`IdentityObservation`、`SemanticLock`、`AtomCandidate`、`PromotionReceipt`。所有产物只保存允许入库的去敏证据，不保存凭据、真实目标地址或敏感响应。

验收：恶意/缺失/矛盾字段 fail-closed；旧产物版本不被新代码默默误读；候选态不得出现 `signed:true`、`replayReady:true` 或正式 registry 写入。

### E1 · 录制后身份观察与语义锁定

录制过程中采集对象类型、名称、编号/编码、稳定业务属性和来源步骤；录制结束后对观察结果做归并。对象有编号时必须名称 + 编号同时一致；只有名称的对象只能生成弱绑定候选并路由人工确认，不能授权破坏性 CRUD。

手动录制开始前提示用户结束后自行关闭录制浏览器；仅用户关闭形成干净收口。录制后必须对“录制时对象”和“重新获取对象”做显式 SAME/DIFFERENT/INDETERMINATE 对比，任何证据缺失不得推成 SAME。

验收：覆盖同名不同号、同号改名、缺号、重复号、分页/排序变化、详情与列表冲突、对象被删除后重建等假一致场景。

### E2 · 候选原子生成与忠实闸

在 distill 现有全 pending 基线之上，允许 LLM/视觉提出 `AtomCandidate`，但候选必须逐步引用原始录制 event、身份观察和页面证据。确定性的 Capture-Fidelity Gate 验证无凭空步骤、无漏译事件、参数类型合法、对象绑定强度满足动作风险。

验收：同一输入的确定性投影字节稳定；模型输出无法绕过 schema、凭据门和忠实闸；坐标点击、脆弱列表序号、仅名称选择不会被提升为可复用 CRUD 原子。

### E3 · 真实 SUT 复验与证据闭环

候选原子只能在联网真实 SUT 上复验。执行自然语言用例时默认开启临时录制，并在执行前允许选择有头或无头；失败后保留完整视频、动作证据、网络取证和附件供定位。视觉模型可检查“操作画面是否符合预期”，但其结论仅作为附件，不能替代 verdict。

每条用例独立生成一个 HTML，必须包含：

1. 自然语言测试用例；
2. 分解后的原子操作；
3. 本次真实执行录屏；
4. 身份观察、语义锁对比、verdict、截图、网络取证等附件索引。

验收：先打通 AI 中台一条低风险只读链，再打通一条创建→按名称+编号重取→更新→删除→后置断言归零的 CRUD 链；医生站/Hi 小助本版先以手录和回放闭环验收。所有验收均需真实环境录像和视觉复核记录。

### E4 · 人签晋升、版本化与撤销

真实复验通过后只生成晋升提案。人工签署时固定候选版本、证据哈希、适用 channel/profile、对象锁策略和回放结果；签署成功才原子化写入正式 registry，并产生不可变 `PromotionReceipt`。晋升阈值（所需跨运行/跨构建成功次数）在实现前单独冻结，不由代码临时猜测。

提供撤销/降级：出现身份冲突、连续漂移、假一致或真实环境回归时，将正式原子降级为 pending/disabled，保留历史 receipt，不静默覆盖旧版本。

验收：未签、证据变化、构建变化、profile/channel 不匹配均拒绝晋升；晋升写入具备原子性；撤销后新 compile 不再选择该版本，历史报告仍可解释。

### E5 · 运行时反馈与有界自愈接合

正式原子每次复用写使用结果、身份对比和失败分类。只有 verdict 已确证 `HARNESS_ERROR` 时，才可进入 P6 的非就地漂移补丁流程；`SUT_DEFECT`、`NEEDS_HUMAN` 和身份不确定不得自愈。补丁经人签和真实重放后形成新版本，不修改旧版本。

验收：证明运行反馈不会写 verdict、不会自动改变冻结 expected、不会因单次成功提升信任等级，也不会因模型建议直接写 registry。

### E6 · 可用性与跨平台交付

把录制、候选检查、真机复验、签署、晋升、选择用例回放和撤销全部暴露到 Casey skill/MCP/CLI；用户操作面仍只需要自然语言。Win PowerShell、WSL、macOS 分别给出权限预检、代理/隧道按需判断和无管理员优先路径；原生 Windows 不依赖 Docker。

验收：由权限有限、模型能力较弱的 agent 按安装提示完成一条真实用例，遇到自动化失败时能正确转入手动录制，关闭后生成候选并再次成功回放；所有失败均有明确下一步，不假 PASS。

## 3. Claude Code 评审预算

Claude Code 使用 `fable high`，按风险而非提交数量触发：

1. 计划评审一次：E0–E5 的信任边界、假一致、自动晋升和回滚设计；只提供相关 plan/schema/关键不变量，不喂全仓历史。
2. 实现终审一次：合并前只审冻结契约、核心 diff、金牌结果和一份真实 SUT 证据索引；已审通过且 diff 未变的文件不重复审。
3. 普通机械接线、文案、重复修订由本地测试和 pi.dev 审核；只有新增 HIGH/P0 风险或关键 diff 改变，才追加 Claude Code 聚焦复审。
4. 评审提示必须要求输出 findings-first、定位到文件/行、无发现即明确 PASS，禁止泛泛复述项目背景。

## 4. 并行与完成闸

可并行开发身份观察旁车、报告/录屏接线、跨平台交互；语义锁 v2 是候选原子和 CRUD 接线的前置硬门，E4 晋升必须等待 E1–E3 真机证据齐全。并行不等于并行写同一冻结面，冲突仍由主会话统一裁决。

完成必须同时满足：冻结验收全绿、全仓 ratchet 无新增问题、真实 SUT 用例逐条有独立 HTML/视频/附件、视觉辅助复核完成、确定性 verdict 可重复、人签晋升和撤销各实跑一次、Claude Code 终审无未处置 HIGH/P0。任何一项缺失只能报告阶段进度，不能宣称闭环自进化完成。
