# entity-c0c2c3-p3-reconcile 学习账

1. 两个各自全绿的冻结契约合成后，必须在组合树复跑；本轮 C2 source 读回与 C3 结构准入只有组合后才暴露 C5 夹具误耦合。
2. 修跨契约交互时先缩夹具到自己的被证义务。给无关步骤补假观察、放宽生产门或改退出期望，都会把真实冲突伪装成绿。
3. 子进程 `status=65` 与 launch 哨兵缺席只证明行为半边；具名 reason 是独立证据半边，不可因捕获困难删除。
4. `process.exit()` 前写 pipe 在当前嵌套/非 PTY 环境会丢诊断；先直驱排除 dispatcher，再用文件描述符直写捕获。环境差异必须靠对照实验归因，不能凭猜测挂账。
5. 被多枚金牌消费的 support 也是冻结面，必须进入明确 owner 的 `testChecksums`；只钉入口测试会留下旁路。
6. 异构评审要看到完整 worktree 和权威文档。首轮发现结构债，修后用同一 TUI 的 `code-review` skill 复审，才能把“方向正确”与“可合并”分开。
