# P6 heal · learn（2026-07-29 凌晨；Steven 令评审收敛后即推 learn，阶段机械推进待 gate 全绿）

## 本契约学到的（按承重排序）

1. **写码前的多轮真异构计划审，是全契约回报率最高的一段。** 五轮（v1→v4.1）逮出的
   「单 rename 冒充多文件事务」「exit 3 语义复用」「布尔 reset 自报」「熔断计量自相矛盾」
   「证据混件不可判别」，任何一条漏到实现期都是返工级；五轮总成本远小于一次返工。
   计划审必须给真仓+允许亲跑（codex 翻 `replay-axes.mjs` 源码实测「axes 不存定位」，
   包内推理永远做不到）。

2. **冻结金牌之间要做互斥矩阵检查，铸造期就做。** A4 与 A5 在各自文本下都对，放进同一
   夹具宇宙互跑才暴露互斥——五轮计划审全部漏过，因为它藏在两枚金牌的具体夹具交互里。
   工序补丁：acceptance-gate 冻结前，把共享场景形状的金牌成对交叉跑一遍（A 的夹具喂 B 的
   断言），互斥在解冻成本最低的时刻暴露。

3. **在既有面上盖新层之前，先证热路径可达（S0 模式）。** P5 的漂移探针从未在生产接线上
   可达（点击步被域锁截走 + `targetName` 字段从未被写），而它的金牌一直绿——因为都
   「从动作轴往下测」，从没测过轴怎么来。任何「消费上游产物」的新契约都该有一个 S0：
   用真生产接线证明上游产物真的会出现，两分支（可达/证伪）各有诚实产物，证伪也是交付。

4. **夹具摆证据、真裁判落裁定。** 本契约全部夹具零手写 verdict——用现役生产投影产三轴、
   spawn 真 `bin/verdict.mjs` 出裁定，连攻击探针的「坏基线」都是真裁判铸的（非目标步
   真 `SUT_DEFECT`）。这让「夹具倒着裁向预定结论」在结构上不可能，也让金牌天然随裁判
   语义演进。

5. **金牌绿之外要有行为探针。** 金牌只证冻结断言面；每笔修复配一次性探针（跑完即删）
   证明新拒付面「真的可达且落对码位」——本契约三轮共 60+ 条，逮出过「声明的拒因在该
   场景根本走不到」（同 ts 重晋升先撞前置校验而非产物碰撞）这类金牌测不出的声明-行为漂移。

6. **契约收缩胜过硬桥。** 复核编排做不成「与正式回放同姿势装配」（域锁+origin 门都不容），
   正解不是造第四条路径硬桥，而是把 v1 复核收缩为 hermetic 专用+生产一律诚实拒
   （exit 64）——假等价面从定性上消失，真机复核 route:human 与 S0 证伪自洽。
   同理 within 降前向兼容注记：复核忠实于生产的弱语义，绝不多读生产不读的键。

7. **码位是契约面，冻结要一次到位。** 「候选 4/6 实现期敲定」这半句让两轮复审空转；
   退出码×拒因×outcome 三表在 acceptance-gate 前就该完全冻结，含 catch-all（1=内部错误）
   与每条具名拒因的归口。

8. **多文件事务的两条铁律：回滚与晋升对称登记全集；基线绑定到证据元组。** journal 只
   登记 events 不登记绑定=回滚把事务拆回单文件；基线只验「晋升后未变」不验「等于提案
   时那份」=晋升前预换基线照样藏回归。两条都各花了一轮复审才闭合。

9. **评审供应方姿势差要入库即用。** grok `-p` 单轮的执行性声明是编造（行号可从包内 diff
   推出）；tmux 真终端+保姆（弹窗精确措辞、静止阈值、勿用 pgrep）才是真多轮。本夜首轮
   grok 评审因此降级为包内推理二意见，扛验证的是 codex 真沙箱+现场活探针——记账时如实
   区分两种证据等级。

10. **route:human 不是欠账，是接口。** 变更型复核、真机 healed→PASS、reset-proof 权威源、
    A4/A5 裁决——全部显式转人并具名记录，机器面才敢说「其余全部为真」。
