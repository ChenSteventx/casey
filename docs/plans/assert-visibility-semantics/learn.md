## 一、修了什么

`tc_wf_publish_states` 末步四轮真机稳定红，真因是**断言口径错、动作对**。真机
探针实测：按 Esc 前「创建时间」DOM 命中 1、可见命中 1；按 Esc 后 **DOM 命中仍 1、
可见命中 0**——浮层视觉关闭但节点不卸载，而现役 `assert.textHidden` 数的是 DOM
命中。作者层注册表把该原子定义为 `toBeHidden`（含未挂载），**签字时的契约本来
就是可见性，实现才是偏离**，所以这是实现纠偏不是语义变更。

改动落在 `lib/replay/intent-observation.mjs`（被 `textHidden` 请求的值改数可见
命中、判据面另起未知读废掉 `safeRead(...,0)` 的 0 回退、提示读取合成同刻快照）
与 `lib/assertion-draft.mjs`（补 `assert.textHidden` 硬映射）。同时堵掉两处
fail-open 缝（护栏 #14）。真机最终码四轮全 PASS，首末轮辅助探针独立复现
`1/1 → 1/0`。

## 二、教训

1. **异构评审必须对着不可变快照跑。** 第一轮评审是对着工作树起的，而工作树当时
   正处在实现代理做变异验证的回退窗口——评审读到空 diff，一本正经报「你声称修的
   四条一条没修」，整轮 12.7 万 token 作废。正确顺序是
   `gate 绿 → commit → 评审对着该 commit → push`；commit 不被阶段互锁拦，这个
   顺序零额外代价。评审报「你的改动根本不在」时，第一反应该是核工作树实况，
   而不是照单全收去「重修」——那会把已经对的实现改坏。
2. **「合并同类项」可能砍掉判别力。** 我把两处重复的可见谓词合并、把选择器
   从回调体内提成参数，看着更干净，实际让金牌固定语料失去判别力——它是靠正则
   匹配 `String(fn)` 判断「这是不是提示查询」的，选择器一挪，采集失败情景再也
   触发不了，V6 当场变红。**替身的判别机制也是接口**，重构前先看替身怎么认路。
3. **拆分采样点等于亲手打开兜底本要防的洞。** 兜底读取的全部价值是**时间**
   （抓短命提示在两次读取之间消失的窗口）。我把不过滤读与可见读拆成两次采样，
   短命提示在两读之间谢幕时第二次合法返回空数组，`textHidden` 拿到 0 判过——
   正是兜底本该防的假绿。codex 实测复现后才发现。凡「同一事实的两个视图」，
   要么同刻派生，要么明确写清各自的时刻语义，不能默认它们等价。
4. **门禁绿会掩盖邻接面的既有假绿。** 本轮 s2 原列十二枚金牌里六枚实测全红，
   其中五枚起浏览器的统一死在语义锁准入门（`replay exit 65`、明写「未启动
   浏览器」）——那道强制层 07-24 前后落地后没复跑这批金牌（护栏 #19 的典型
   踩法），于是七份 prd 至今扛着 `passes: true` 的假绿。**把邻接清单开大一点
   就会撞见别人的债**；撞见了要如实挂账、给差分证据，不能因为「不是我打红的」
   就悄悄从清单里删掉。
5. **真机抖动要跑够轮次才看得见，而且不能当噪声抹掉。** 最终码五轮里有一轮
   在 `atstep_1` 就 `locatorError` 级联失败。失败点在定位层、不在本次改动的
   文本采集层，且系统落了 `NEEDS_HUMAN` 没假绿——但它必须写进账里，不能只报
   四轮全绿。
6. **探针跑不通时，别急着判「环境不行」。** 探针连撞四个坑：执行目标要先铸权
   再启动浏览器（隧道是保真代理形态）、登录预备动作在慢渲染下会误判成「已登录」
   （只给表单 3 秒）、要等路由加载遮罩退场、列表卡片真类名是 `.agent-card` 而不是
   剖面 `countSelector` 写的那个。每一坑都靠**一次只加一条结构诊断**（路径、
   计数、类名频次）定位，没有一次是猜中的。

7. **钉子要钉不变量，不要钉当时那条实现路径。** V10 第一版靠替身「按调用顺序」
   作答来制造窗口，但没断言查询次数——codex 复审当场指出：仍分两次采样、只是把
   可见那次读在前的实现，会拿到 `actual:1` 与 `NEEDS_HUMAN`，反把 V10 蒙绿。
   加固成断言「提示查询次数恰为 1」后，判据才从「顺序」变成「次数」，也就是
   真正的不变量：**两份视图必须来自一次查询**。变异实测印证（两次采样 → 红在
   V10，报文「实际 2 次」）。
8. **修一处缝，要顺手查同族。** 复审在同模块又找出两处同型缺陷：回复快照分开读
   数量与末条文本（新失败回复消失后会读回旧的成功回复，`replyContains` 假绿）、
   按钮观察分开读命中数与禁用数（按钮禁用时被计中、随后卸载使禁用数归零，
   拼成 `hits=1/disabled=0` 让 `buttonState enabled` 判过）。都是「同一事实的
   两个视图被分开采样」。**这一类要当成模式来扫，不是逐个撞见才修。**
