# 真机只读 spike 清单（route:human，A10 交付物）

> **2026-07-22 采集状态**：一、二、五及三通道核心问题已由机器只读探针采齐（Steven 带外确认 autotest 后授权真机），结果落 `evidence/realmachine-spike-findings.md`；余留三项（bindAgent 抽屉配方、同名对抗预置、详情页 ID 人工目检）见该文档第五节。

> 目的：为「名称+平台 ID 联合定位」补上唯一缺失的事实——真机上智能体的平台 ID 到底从哪读。
> 全程只读：只登录、只看、只记录；不建不删不改任何对象。账户按纪律带外确认后再动真机。
> 采齐后交回，即可另立契约把 ID 读回接进编译/回放（本轮已预留消费缝）。

## 一、智能体列表页（/agent/list）

- [ ] 列表条目 DOM：右键检查任一智能体条目，记录条目根元素的全部属性（尤其 `data-*`、`id`、`key` 类属性）——有没有平台 ID / 编码？
- [ ] 条目可见列：除名称外是否渲染编码/ID 列（含悬浮提示）？
- [ ] 搜索框：分别用「名称」和「编码」各搜一次，记录请求 URL 与响应里每条记录的字段名（浏览器开发者工具网络面板，脱敏后只记字段名与 ID 形态，不带业务数据）。
- [ ] 列表接口响应：记录返回记录的完整字段清单（id / code / name / 版本 / 修订号等，只记字段名与样例形态如「20 位数字」）。

## 二、点击打开详情（/agent/detail）

- [ ] 点击条目后的 URL：是否携带 ID（路径段或 query）？记录完整路由形态。
- [ ] 详情页 DOM：页面上是否渲染平台 ID / 编码（含「复制 ID」类控件）？
- [ ] 详情接口：打开详情时的请求 URL 与响应字段清单（同上只记字段名与形态）。

## 三、同名对抗观察（只读）

- [ ] 若平台已存在同名智能体（或由管理员预置一对）：搜索该名称，记录列表如何区分两条（不同 ID？不同编码？创建时间列？）。
- [ ] 分别打开两条，记录各自 URL / 详情接口的 ID 差异——证实「同名不同 ID」在真机的可观察形态。

## 四、bindAgent 真机配方复核（D1 挂账）

- [ ] 打开任一工作流画布，找到绑定智能体的交互位置：是节点配置抽屉内的选择控件吗？控件形态（下拉/搜索选择/弹窗列表）？
- [ ] 选择列表里每个选项渲染什么（仅名称？名称+编码？）；选项 DOM 有无 ID 属性？
- [ ] 选中后抽屉内如何回显（可作回放回读锚）；保存后节点上如何呈现。

## 五、searchOpen 容器类名采样

- [ ] 智能体列表条目容器的真实类名/结构（对应 `profile.agents.itemContainer` 待填值；chat-sut 夹具当前用 `.agent-item`）。

## 记录纪律

- 凭据、账号、真实业务数据、完整响应体一律不进记录；只记字段名、DOM 属性名、ID 形态（位数/字符集）与路由形态。
- 每项配一张脱敏截图或字段名清单即可；采集结果落 `docs/plans/entity-ui-wiring/evidence/realmachine-spike-findings.md`。
