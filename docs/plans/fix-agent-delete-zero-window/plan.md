# 智能体删除连续归零窗口修复计划

## 目标

修正 `agent.delete` 的删除后归零证据计时：稳定期必须从本轮连续零样本的首个样本开始计算，不能使用后置检查启动时间冒充连续归零时间。

## 步骤

1. 冻结纯函数零 `SUT` 反例：2.9 秒才首次归零时，3.2 秒即使样本数达标也不得背书。
2. 冻结加载态与目标重现分别清空连续零窗口的反例。
3. 修改 `advanceAgentDeleteZeroEvidence`，显式维护连续零窗口起点，并同时要求窗口满 3000 毫秒、连续样本数达标。
4. 只运行定向纯函数、静态语法和 checksum 门禁；不连接或回放任何 `SUT`。

## 验收点

1. 首个零样本在 `elapsedMs=2900`，第三个零样本在 `elapsedMs=3200` 时，`ok` 必须仍为 `false`；持续至 `elapsedMs=5900` 且样本数达标后才能为 `true`。
2. `busy=true` 必须把样本数与连续零窗口起点一起清空，后续零证据从新的零样本重新计时。
3. `matches>0` 必须把样本数与连续零窗口起点一起清空，后续零证据从新的零样本重新计时。
4. 验收只证明纯函数证据折叠语义，不冒充真实页面删除或真机完成。
