# term-guard — plan（统一语言强制兜底：开发输出/文档遵循 CONTEXT.md 领域词汇）

## 背景与边界

DDD（领域驱动设计，Domain-Driven Design，来源 Eric Evans 2003）在语言上的核心是统一语言（Ubiquitous Language）：开发流程里，输出和文档要一致使用领域约定词汇（即 `CONTEXT.md` 四列制登记）——不造词、不用弃用别名、不机翻、需要时给描述或来源、不裸用比喻。本契约把这条纪律作用在「我的开发输出/文档」上、变机制强制。用户给的比喻规则 + 术语翻译规则是其中条款。

本会话反复违例（加粗英文术语、裸用比喻、误用弃用别名）暴露两类缺口：`loop-kit` 的 `term-lint` 管弃用别名与加粗英文，但漏中英混合加粗跨度（如 `**baton = 中文**`）、且不管比喻与机翻。term-guard 补这些漏检。

范围：仅开发输出/文档。产品侧同款过滤（判 SUT（被测系统，System Under Test）输出内容用语）走质量接口 / LLM 评分员（内容好不好，`CONTEXT.md` 已登记 `chat`），非本契约；两侧唯一硬不变量都是不进 `verdict.mjs`（裁判零 LLM，护栏 #15）。

不改 `loop-kit` 引擎（ADR-0001 字节一致）：全落 Casey 侧 `bin/` + `.claude/settings.json`。乙的 LLM 判断不确定（nondeterministic：同输入不保证同输出），只用打桩（stub：注入假判定）验确定性外层，真 LLM 走 route:human；证不出路由人（NEEDS_HUMAN）、不 fail-open（失败默认放行，护栏 #14）。

## 被强制的规则（统一语言的条款）

比喻：
- R1 能不用就不用；仅理论晦涩时可用。
- R2 严禁对术语裸用比喻（无上下文）。
- R3 一定要用则另起一行，格式：本体：… / 喻体：… / 关联是：… / 联系是：…。

术语翻译：
- R4 不机翻术语；有专业译名用专业译名 + 溯源来源。
- R5 无专业译名则术语后括号加描述。

登记词汇（`term-lint` 已管，term-guard 承接不回退）：
- R6 用 `CONTEXT.md` 登记词汇，不用弃用别名、不加粗未登记英文。

不满足 → 不允许输出（甲硬拦 / 乙拦或路由人）。

## 组件

1. 钩子甲 `bin/term-guard.mjs`（新建，Casey 侧，零 LLM）：
   - 比喻格式校验（R3）：文本段内（空行分段）出现任一字段标记（本体/喻体/关联是/联系是）即触发校验；合规要求四字段各恰好一次独占一行、内容非空，任一字段与他物或别字段同行、或缺失、或重复、或内容空即硬拦。
   - 未登记加粗英文（R6）：加粗跨度内英文未命中 `CONTEXT.md` 登记即硬拦，含中英混合加粗跨度（补 `term-lint` 漏检）；弃用别名明文使用同拦。
   - R5 撤除（2026-07-01 修订）：裸用未登记英文不硬拦——「英文是否需描述」是语义判断，确定性正则会对专名 / 文件名 / 里程碑标签 / 常用词全误拦（实测 `HANDOFF.md` 459 处）；仅「英文紧跟中文括号描述」者作 R4 机翻候选交乙。
   - 引用豁免（唯一层 = 反引号代码体；自然语言引号一律不豁免，codex round5）：R3 声明块不做任何豁免（反引号包住的声明块仍判红，防 `` `本体：`A `` 逃检）；R6 加粗英文与 R5 候选只豁免反引号代码体（引号内加粗英文判红）；弃用别名只豁免反引号代码体，且反引号内的别名外抛乙 `alias-ref` 候选（伪装使用交语义层判「提及 vs 使用」——确定性死角）。补 `term-lint`「不分使用与引用」的粗糙处（本会话「提及某弃用别名」被误拦即此）。
   - 确定性预筛：检测候选比喻信号词与候选未登记术语，输出候选清单供乙。
   - 挂 `.claude/settings.json` 的 Stop 钩子链，独立新条（不改 `loop-kit` 的 `hook-stop.mjs`）。
2. 钩子乙 `bin/term-judge.mjs`（新建，Casey 侧，LLM 评分员）：
   - 只吃甲的候选清单，空则不调 LLM。
   - 判 R1/R2/R4：候选是否属未声明且不必要的比喻、是否机翻术语。
   - 评分员非 Claude 家族（异构冗余），复用 `review` 道 DeepSeek/codex 路径。
   - 判违例可信 → 拦并给理由；不确定 / 评分员不可达 → 路由人写 `loop/inbox.md`（不 fail-open）。
   - 打桩接口：注入假判定供 hermetic golden。

## 验收点（命令化 hermetic）

甲（全确定性）：
- [命令] R3 正：四字段各独占一行、内容非空 → 放行（exit 0）。
- [命令] R3 反：缺字段 / 字段空 / 以喻体起无本体 / 本体不在行首 / 四字段挤一行（或两字段共行）/ 同字段重复独占多行 / 空字段被同名非空补票 / 反引号包住的声明块 → 非零。
- [命令] R6 反：加粗未登记英文（含 `__粗__`、多行、超 80 字、中英混合、自然语言引号内）/ 弃用别名明文使用 → 非零。
- [命令] 引用豁免（唯一层=反引号代码体）：反引号内加粗英文/别名 → 甲放行（别名同时外抛乙 `alias-ref` 候选）；自然语言引号内加粗英文/别名 → 判红；反引号包住的 R3 声明块 → 仍判红。
- [命令] R5 撤除：裸用未登记英文（专名 / 文件名 / 常用词）→ 放行；裸内嵌大写 CamelCase → 外抛乙 `newterm` 候选；小写常用词 → 不外抛。
- [命令] 预筛：含比喻信号词 → 输出非空候选清单。

乙外层（打桩评分员，hermetic）：
- [命令] 候选 + 桩判违例 → 非零 + 理由。
- [命令] 候选 + 桩判不确定 → 路由人（写 inbox、不拦不放）。
- [命令] 候选 + 桩不可达 / 报错 → 路由人（不 fail-open）。
- [命令] 空候选 → 不调评分员、放行（证不空跑 LLM）。
- [命令] `casey selftest --tier1` 无回归。

## route:human（真 LLM，gate 绿 ≠ 完成）

- 真非 Claude 评分员对真输出判未声明比喻 / 机翻的准确率（判 FAIL 可信、判 PASS 仍人抽检）。
- 密钥接线后端到端一次真判。

## 红基线

甲 / 乙脚本未建时命令化 golden 跑红；实现落齐转绿。反向红用合成坏文本 / 打桩判定，不改真 `CONTEXT.md`、不动 `loop-kit` 的 `term-lint`。

## 完成判据

gate GREEN（甲全确定性正反向 + 乙打桩外层 + selftest tier1 无回归）+ codex 异构评审收口。乙真 LLM 接线 + 端到端走 route:human。产品侧质量接口的同款过滤另议、非本契约。
