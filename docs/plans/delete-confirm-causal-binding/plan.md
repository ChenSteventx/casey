# 删除确认弹层因果绑定计划

## 目标

修复 `workflow.deleteByName` 的确认动作可能命中无关弹层的问题：删除触发前记录已有可见弹层，触发后只授权唯一新出现的物理弹层；发现确认文案和执行确认都只能使用该授权，且授权只能消费一次。

## 非目标

- 不修改裁定、报告、事件或断言 schema。
- 不改变其它原子的动作选择。
- 不启动或连接浏览器、fixture、fake-SUT、网络或真实 SUT。
- 不处理 loop 改革。

## 改动

1. 在 `lib/workflow-delete-domain.mjs` 增加纯身份分类函数，按物理同一性从触发前后快照中选出唯一新弹层。
2. 删除触发前抓取可见弹层基线；点击后有界等待唯一新弹层并立即 pin，把目标名、物理句柄和 pin 一起写入页级一次性授权。
3. `inspectWorkflowDeleteConfirm` 只检查已授权弹层。
4. `performWorkflowDeleteConfirm` 在任何动作前消费授权，只允许在同一物理弹层内确认；所有成功和失败路径都清 pin、释放句柄。

## 验收点

- C1：触发前已存在的弹层不被当成新弹层。
- C2：触发后恰有一个新物理弹层时才能形成授权；零个或多个新弹层均拒绝。
- C3：同一 DOM 节点的不同句柄包装仍判为旧弹层，不靠 JavaScript 对象引用猜身份。
- C4：确认发现与确认执行都只使用授权物理弹层，不重新选择任意唯一可见弹层。
- C5：授权在确认动作前一次性消费；目标名不符、句柄替换、pin 丢失、按钮缺失或点击失败均清理授权并拒绝。
- C6：`node --check`、零 SUT 静态金牌与 `git diff --check` 通过。

## 可观测性

- 本轮只证明身份分类与生产接线结构，不证明真实 Heren 弹层时序。
- 真实弹层出现延迟、框架替换节点以及确认后的删除结果，必须由主线程在真实 SUT 上复跑并结合录屏复核。

## 停止条件

- 若实现需要修改裁定、报告 schema 或事件 schema，立即停止并交主线程裁断。
- 若零 SUT 验收无法证明生产接线，保持未完成，不以源码存在冒充通过。
