## 教训（可迁移）

1. **`indexOf` 源形态钉的定义先于调用陷阱**：函数定义行与调用行共享同一子串时，
   `indexOf` 首命中定义、次序断言恒真——钉空转。锚定调用点要用调用点独有文本
   （赋值前缀）+ 唯一性断言 + 关键分支次序断言三件套；能行为级驱动就别用源形态钉。
   这条线三次栽在「静态钉钉不住行为」，r5 的三件套是底线写法。
2. **突变要外科式**：粗切块把语法切破，红因变成 parse 错——任何测试都会红，
   证不了目标钉的判别力。突变必须保持 `node --check` 过，红因必须是目标断言文案。
3. **`wx`(O_EXCL) 的独占在建文件刻、内容在后**：并发窗口读到空文件要有界重读 +
   区分「在场未 settle」拒因；消费标记只看在场不解析内容（解析失败当未占用是
   fail-open 方向，反着来）。
4. **评审运行错误四列分账**（超时无终局/会话限额/HARNESS_ERROR/上游忙）与结论
   严格分开——六轮里三次运行故障，没有一次被冒充成结论。
5. **不实文案与代码同权重**：PRD observability 里一句「R11c 已直接执行 executeTier2」
   的过头话，和空钉本身一样是要修的缺陷——文案宣称的观察面必须与钉的实际能力一致，
   证不出的归 route:human。
