# sut-503-diagnosis · 收口复盘

## 结论

- 2026-07-23 两个不同实例的详情页双 `503` 是有正式回放取证的历史事实；
  run-1 的 `SUT_DEFECT` 保持有效。
- 2026-07-24 候选实例与 2026-07-27 新唯一实例首次打开均为双 `200`；
  “标准表单新建骨架智能体稳定双 `503`”这一强假设已被证伪。
- 截至 2026-07-27 当前环境不可复现。研发应先查失败时点的服务日志、共同下游、
  创建事务/详情子表初始化，以及 7 月 23 日到 24 日之间的部署或配置变化。

## 可复用教训

1. **HTTP 事实、进程退出码和四态要分开。** r3 的 exit 2 来自取证后的后置证据门，
   不会把此前已经收到的双 `200` 改成失败；同理，run-2 的 `PASS` 也不会让归因窗外的双
   `503` 消失。
2. **先判样本资格。** r1/r2 在确认创建前中止，目标响应和详情打开均为零，不能计入
   `SUT` 样本。
3. **历史缺陷与当前可复现性可以同时成立。** 新样本恢复不能撤销旧
   `verdict.json`，旧样本也不能支撑“现在稳定必现”的扩大表述。
4. **最小技术闭环优先。** 当前双 `200` 已足够否定强假设；继续扩大浏览器矩阵的收益低于
   查服务端日志。只有日志指向初始化时序或单一字段时，再补一项有目标的复验。
5. **清理证据只背书真实可观察面。** 本轮唯一名称从 1 清到 0；卡片副标题不是可靠编码面，
   因此编码归零保持未决，不用错误 DOM 假设制造假完整。
