# sut-503-diagnosis · 503 缺陷诊断计划

## 目标

对 `real-uat-attestation` 真机 UAT 已捕获的两条详情页 `503` 做有界诊断：

1. 在批准的测试账户和单实例回环隧道前提下复现；
2. 用差分矩阵收窄触发条件，并保留最小脱敏网络证据；
3. 铸造可直接交研发的自包含缺陷上报包；
4. 以对抗性反证检查实例、账户、同名、缓存、时序、路由参数与工装误点等替代解释；
5. 清理本轮创建的全部 `atl_` 测试件。

本契约只诊断和上报，不修改被测系统或 Casey 生产实现，不修改冻结断言，不代替研发修复。

本轮按前期探索口径执行：优先跑通“复现 → 收窄触发条件 → 缺陷包 → 研发可行动下一步”的
最小技术闭环，不扩张成安全加固或穷尽式根因工程。只保留 Casey 已生效的凭据、测试数据、
确定性裁定和清理底线。

## 已知基线

- `real-uat-attestation` 的 run-1 在唯一定位并成功进入详情路由后，由确定性
  `verdict.json` 把本步裁为 `SUT_DEFECT`；同一步归因到
  `agentPlus/queryPlus` 与 `agent/setup/getAgentDetail` 两条 `503`。
- run-2 的新实例仍出现相同两条 `503`，但落在本步因果归因窗外，所以机械裁定为
  `PASS`；同次终帧视觉复核为 `INCONSISTENT`。这证明“裁定作用域不同”，不证明缺陷消失。
- 历史两实例复现已否定单一实例偶发这一弱解释；本轮仍需对触发变量做更细的隔离。

权威历史证据见
`docs/plans/real-uat-attestation/evidence/uat-run.md`，本轮新增证据统一落
`docs/plans/sut-503-diagnosis/evidence/` 和 `runs/sut-503-diagnosis/`。

## 三路分工

### ① 真机差分定位

本轮唯一允许接触真实 SUT 的执行者。先核 `doctor`、单实例隧道和两段真实联网；不读取或回显
`.auth/`、`site.json` 内容。只创建、删除自己带 `atl_` 前缀的测试实体。

输出：

- 复现账与每次探针退出码；
- 变量隔离矩阵；
- 最小脱敏请求/响应事实；
- 因果边界与仍未决变量；
- 名称、编码等多面归零的清理证据。

### ② 上报包铸造

只读既有和①新增证据，不接触任何 SUT。输出
`defect-report.md`，清楚分开已证事实、推断与待研发确认项。

### ③ 对抗性反证

只读源码和证据，不接触任何 SUT。输出
`adversarial-analysis.md`，逐项记录替代假设、可观察预测、证据与
“证伪 / 支持 / 未决”状态。

## 验收标准

1. 真机前置逐项有结果；任何前置不满足时立即停止真机行为，不降级到假 SUT。
2. 新增网络证据只保留方法、端点路径、状态、必要响应头类别和脱敏响应体形态；
   不含凭据、Cookie、真实目标地址或业务数据。
3. 差分矩阵至少覆盖：新实例与历史实例、首次打开与再次加载、两端点是否独立失败，
   以及表单配置或详情路由参数中实际可安全隔离的变量；无法隔离的项如实标未决。
4. `SUT_DEFECT` 结论只引用确定性 `verdict.json` 和其取证链；浏览器探针只用于收窄原因，
   不由模型自行改写四态。
5. 缺陷报告包含影响、自然语言复现前提、期望与实际、重复性、证据索引、边界和研发问题。
6. 对抗性反证覆盖实例、权限、同名、缓存/时序、因果归因窗、路由参数、表单字段、
   清理残留、身份读回和端点连带故障。
7. 本轮创建的 `atl_` 测试件须按本轮唯一名称严格查询归零；额外身份面只有在能可靠读回时才核，
   读回假设不成立则标为诊断工具边界，不为补证扩张实验。
8. 文档通过统一语言检查，证据索引中的本地路径存在；用户原有未提交现场保持不变。

## 停止条件

- `doctor`、账户带外确认、单实例隧道或两段联网任一不满足；
- 页面形态变化导致无法唯一锁定本轮自建测试件；
- 清理无法严格归零；
- 任一步可能读取、记录或回显凭据与真实目标地址；
- 需要修改生产实现、冻结断言或替用户做人签。
