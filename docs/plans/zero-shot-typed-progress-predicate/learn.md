## 本契约沉淀的教训

1. **前提审要前置，本契约用代价实证了一次。** R1/R2 两轮评审逮到的全是计划前提错
   （「按肯定/否定划线」的划线标准、「`pageCount` 不受截断影响」的豁免理由），不是实现笔误。
   三次收敛每次都是实测推翻推理。后续契约（guard-net 起）已改为 GRILL/plan 在实现前先送异构前提审。
2. **承重可达性主张必须双向探针。** 「before 截断不可达」用探针证实成立，但同样的「不可达」
   直觉在脱敏抑制上不成立（grok 用反例证伪）。可达性主张一律逐条实测，不接受类比推广。
3. **规范文与统一规则对撞是真风险不是措辞洁癖。** R2 收敛后 plan 残留的 R1 旧段被复审定为
   Medium：后人照旧文「修回」豁免会把 F1 假绿请回来。收敛型修订必须全文清扫旧规范句，
   叙史句（描述被证伪的旧理由）保留并标明已证伪。
4. **看门狗判据不得与注入文本同串**（已入全局记忆 watchdog-grep-must-not-match-prompt-echo）：
   tmux 保姆 grep 裁定串第一轮假阳性——匹配到了提示词自己的回显。完成判据改用完工标记+空闲提示符。
5. **评审供应方会静默挂起。** pi 复审 1h43m 只烧 1 秒 CPU、零输出——判死换跑方并按实际输出记
   HARNESS_ERROR，不改写成供应方不可用。判活看 CPU 累积不看进程存在。
