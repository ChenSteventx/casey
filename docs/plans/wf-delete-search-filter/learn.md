# learn · wf-delete-search-filter

## 这轮学到什么

1. **诊断假设要在动刀前重侦察一遍**。岔口裁定时的表述是「删除步缺回列表导航」，
   动刀前侦察发现导航与就绪锚都在（post-nav 先例早已应用），真根因是搜索姿势
   （Enter 旧知识残留）——修法从「补导航」缩到「换触发」，爆炸半径小一号。裁定封套
   （atom 级、不动已签件）不变时，机制按证据修正并回报确认即可，不必推翻重裁。
2. **「从未走通过」家族的传播模式**：同一 seam-1 知识（Enter 不过滤）在 open 侧已修
   （search-first、readback），delete 侧还残留——一个真机新知识落地时要 grep 全部
   同姿势调用点（本例 `key: 'Enter'` 三处：agent 侧合法、delete 两处残留），别只修
   触发发现它的那一处。
3. **冻结面冲突的两条路**：改冻结件（checksumAmendment+人签，重）vs 实现让路
   （零冻结字节，轻）。让路的前提是冻结断言为包含式/兼容式——本例 post-nav S2 是
   `includes('press')`，惰性保留 Enter 即可满足；若是精确序断言就只剩人签一条路。
   设计金牌断言时尽量用包含式钉意图、少用精确序钉实现，给未来姿势演化留路。
4. **双冻结面一致性是评审的真价值点**：grok 的 Medium 不在实现（实现无缺陷），在
   plan 冻结正文与金牌冻结断言对「Enter 是否退役」互相矛盾——v2→v3 演化时只顾金牌
   与代码对齐、忘了 plan 也在 checksums 里。修订实现方案时按 testChecksums 清单
   逐件同步，别只改会跑的那件。
5. **gate 后的 `git checkout` 还原动作只适用于已提交 PRD**（主树纪律）；对工作树里
   未提交的 PRD 更新会把活干丢（本轮实证一次，重做）。
6. **看门狗判据第二课**：grok TUI 批准后瞬时空闲会假触发「完成」；换成裸
   `VERDICT: ` 行匹配（提示词回显带反引号不撞）后零误报。
