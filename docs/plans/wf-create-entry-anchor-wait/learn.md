# learn · wf-create-entry-anchor-wait

## 这轮学到什么

1. **压线时序预算是「环境变了才炸」的潜伏缺陷**。编译 nav 后锚定窗（quietPoint 2.5s +
   附着 1.5s）对 07-02 时代的页面够用，页面变重（SPA 渲染尾巴 3.5s）后就骑在窗沿上——
   08-04 傍晚赢、08-06 晨输，同一链路同一代码。判定这类问题要**定量**（本轮：只读探针
   每 500ms 采样按钮可定位耗时），别拿「昨天还好好的」当反证。
2. **就绪锚要绑 emit 同一语义锚，预算耗尽不改判**。等待与判定分离：锚只解决「什么时候
   开始判」，判定仍由身份门做——耗尽照发 emit 走 absent fail-closed，失败路径零行为差。
   这样等待逻辑永不可能把 fail-closed 弱化成 fail-open。
3. **hermetic 金牌可以钉「时序行为」**：迟挂载替身（count 先 0 后 1）+ emit 时挂载标志 +
   采样计数三件套，把「真等了、等到了才点、耗尽有界」全部钉住，无需浏览器。
4. **评审方的中途疑虑要看它自己有没有实测收掉**。grok 思考块草拟过 CHANGES_REQUIRED，
   正文逐条实测否证后终局 APPROVE——收据把两段都入档，不挑好的读。
5. **失败路径的时长预算是新的观察面**：+15s 等待在成功路径几乎不花（按钮几秒内出现），
   但失败路径全额支付、压缩看门狗余量（pi Medium）。带预算的等待合入后，首次真机跑
   要记录失败路径总耗时，别等 watchdog 咬了才知道。

## 与前一契约（wf-crud-sleep-import）的接续

sleep 导入修复让 create 原子第一次在真机走完七步（全 emit、如实 fail-closed）——正是
这次「跑通了但没锚上」的失败暴露了本竞态。两个契约合起来才等于「B4 编译在现役页面
可稳定推进到真判定」。
