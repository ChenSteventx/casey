# learn · semantic-name-instantiate

## 这轮学到什么

1. **观测先于修向，一次就能省掉整轮猜测**。B4 五到八跑连着四次在 `workflow.open`
   撞墙，先后押过页面形态、页签过滤、渲染时序、隧道空壳四个假说，全错；上一契约
   花两条诊断 notes 买来的观测，第九跑一次就把真因摆出来：真名探针 5ms 命中、
   页面正常，emit 却 0 命中——差别只可能在定位串本身。
2. **模板与实例化的边界要在「落盘」与「定位」之间划**：落盘必须留模板（回放才能按
   各自 `ctx` 回填），定位必须用实例化名。此前系统只在 `fill` 的 `value` 上做了这个
   区分，`semantic.name` 漏了——于是 `workflow.open` 这个唯一把动态名放进 `semantic.name`
   的原子从写下那天起就没在带模板的目标名下走通过。
3. **改定位核心必须全仓扫描，抽样必漏**。首版给三个函数加 `ctx` 参数，邻接金牌全绿，
   但全仓 205 个金牌里有两个用 `indexOf('resolveCandidate(page, ev)')` 这样的字面
   文本判接线顺序，当场被打红。改法随即让路成零字面变更的纯投影，并把「这三处字面
   不许动」写成金牌自钉——把踩过的坑变成机器判据。
4. **不变式要么全覆盖，要么别声称全覆盖**：pi 逮到投影只覆盖通用路径而专用身份门
   在其之前分支——当前无路径能把模板送进去、且真到了也 fail-closed，但自钉的措辞
   已经比实际强。修法不是改措辞而是把覆盖做实（投影上移 + 覆盖面自钉五处分支）。
5. **红证复现姿势有安全与不安全之分**：`git checkout <rev> -- <file>` 写暂存区
   （本仓已有一起把回退带进提交的事故），`git show <rev>:<file> >` 不碰暂存区——
   本轮起两侧评审提示词都显式点名这条纪律，评审方照做。
