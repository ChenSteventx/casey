# learn — draft-cli（light，2026-07-02）

六阶段全走完（grill 四机械决策 → plan → accept 红先行五红 → loop gate GREEN → codex 两轮 R2 PASS → learn）。沉淀四条：

1. **薄 CLI 不等于零风险面**：函数层四轮评审收口后，命令化层自己又被打出 4 发现——全在「函数层假设由调用方保证」的缝上（caseId 可信性、旗标形状、路径拼接）。CLI 是不可信输入的第一道闸，函数层的前置条件在这里逐条变成显式拒绝，不能指望「反正函数层会兜」。
2. **一致性闸的「缺席」分支别漏**：三方一致检查写成 `!== undefined && !==` 就是给缺席开了门——证不出一致与证出不一致同罪（fail-closed 的完整式：缺席/畸形/不符三态全拒）。与 p4-drafter R1-F1（expected 缺席混过形状闸）同构，同一课两次上，值得进 checklist：**每写一个「X 与 Y 一致」的闸，问一句 X 缺席时走哪条分支**。
3. **进文件名的标识符必须验形状**：`caseId` 拼进产物路径就是路径注入面，白名单字符集（`^[A-Za-z0-9_-]+$`）一行关掉整类穿越。同型缝在 `compile.mjs`（同样拼 `flow-<caseId>.json`）——挂账顺手同修，不在本契约扩面。
4. **对 codex 发现的第三种处置**：采信改码、拒绝有据之外，还有「修正采纳」——F4 的分类论证（闸拒→65）成立，但项目先例（`compile` 文档明写 1=凭据门拦）更重，改法是修 spec 措辞 + golden 钉住既定约定；R2 认可该裁量。评审发现指向的是「不一致」，消解不一致的手段不必然是改代码。
