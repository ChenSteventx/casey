# learn — chief-bringup（direct，2026-07-03，真机 bring-up）

真机停站②三轮迭代（看门狗死 → fail-closed 落诊断 → 零非 unique 步全流程跑通、抵凭据门），五只读探针定点。沉淀五条：

1. **hermetic 绿 ≠ 真机绿，但探针能把差距压成清单**：五个只读探针（导航挂点/路由通路/面板时序/真实可访问名/发送彩排）把四处假设差全部定点成机器事实——点击被 `hr-submenu`/spacer 拦、真名带省略号、面板间歇吞点、`fill` 即 enable。经验：真机 bring-up 前先跑一轮「假设核对探针」，比直接跑编译再从看门狗尸体上倒推便宜一个数量级。
2. **二手结论会过时**：regress 的「`fill()` 不触发 keydown、按钮保持 disabled」在当前真机已不成立（`fill` 即 enable）——keydown 垫因「无害且防御性」保留，但据此上强设计（如改冻结枚举）就会为过时结论付大代价。移植时对源仓的每条「实测结论」标注采集日期、真机重验。
3. **失败要死得快、死得有报告**：失败步 30s 级后置等待堆积把 120s 看门狗撞死、连 fail-closed 诊断都不落——「快死」不是性能优化，是可观测性需求。凡后置等待必挂在「本步成功」条件下。
4. **路由导航 > UI 点击（能选就选）**：应用壳导航（侧栏点击）受渲染时序/遮挡/同名多匹配三重威胁；路由直达一击即中且天然幂等。原子编译知识应优先吃通道剖面 routes、点击留兜底。
5. **凭据门的误伤也是信号**：`token` 关键词命中的是路由名（`getTempTokenForApi`）非凭据值——门按设计 fail-closed。处置（源头打码 vs 形状豁免）动护栏 #7 机制面，挂账 Steven 拍板，绝不代签。另记：真机回复长度恒 4 字符（彩排两次一致）——draft/人签时须人工看一眼回复质量。
