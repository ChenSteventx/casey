# e2e-chain — learn（light，codex 四轮 R4 PASS）

上下文：hermetic「文本→报告」全链首次贯通（十站集成金牌 C1–C8），零集成缝、零 lib/bin 改动；
codex 四轮 15 发现（11 采信 + 2 修正采纳 + 2 证伪留案）全部打在「金牌绿是否空洞」上。

## 1. 首跑零缝是接缝纪律的迟到红利

十站链 bring-up 一把 8/8 绿、三轮加固的钉死期望（事件序列/断言原子挂靠/回放行数/命中率）全部一次
命中零调参——不是运气，是每相收口时的 schema 冻结、caseId 绑定闸、fail-closed 契约码把接缝提前钉死了。
接缝纪律的成本在各相契约里分期付，集成时兑现。

## 2. 集成金牌的对手是「空洞的绿」，评审要专打断言强度

单元金牌的对手是实现缺陷，集成金牌的对手是自己：exit 0 + 文件在场 ≈ 什么都没证明。codex 四轮
15 发现无一是链本身的缺陷、全是金牌断言太弱（跟随产物动态推导/只验存在不验内容/扫描范围窄）。
写集成金牌的纪律：期望集做成冻结常量（deepEq 钉死）、绝不从产物反推；「有产物」升格为「产物内容
与源头期望逐字段吻合」。

## 3. 真回放证据链：找「伪造不出」的字段，别给夹具加接口

「怎么证明真跑了浏览器」不必改冻结夹具加请求计数——产物里本就有伪造不出的证据：动作轴
`resolution:'unique'`（真 DOM count===1 才产）、`identityReadback.ok`（真填真回读）、取证轴保存 POST
按 `attributedStepId` 归因 + 信封实判、后台轮询 null 归因。集成金牌优先消费既有取证面，修正采纳
优于扩夹具接口。

## 4. hermetic 边界要主动设陷阱，不能只靠「没读到」

凭据 env 毒化（删 `AT_CREDS_*`、`AT_CREDS_FILE` 指不存在路径）让「链上任何站破 `--skip-login` 纪律」
从静默通过变成必红；`cwd: tmp` 让相对路径误写从漏检变成落进扫描域。射程外的（fs 级「证明未读」、
进程网络白名单）明说留案并指认既有机制（`verdict-purity-guard`），不造弱版监控装样子。

## 5. 修正采纳与证伪都要给「指认」，不是给借口

R1-F3 网络 trap 证伪时指认了护栏 #15 的机制守点；R2-F3 证伪时指认了可移植性矛盾（仓根 site.json
缺席才是常态）。证伪的说服力来自指出「谁在守这个面」或「该场景为何不存在」，评审员两轮都收了。

## 挂账（不静默丢）

- hermetic 贯通 ≠ 真机端到端（护栏 #16）：真机 compile bring-up + 人签在场，route:human 记
  `prd-e2e-chain` observability。
- 相5 自愈仍未吃过真场景（happy 链不触发 HARNESS_ERROR，诚实交底不变）。
- 链金牌运行 ~35s（两次 chromium 起落），不入 tier1（hermetic 但非秒级）；gate acceptance 位是对的家。
