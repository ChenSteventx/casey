# agent-id-readback — GRILL（full）

## 问题是什么

「名称+ID 双定位」的智能体侧一直缺最后一环：编译/回放路径没有消费平台 ID。2026-07-22 真机只读尖峰（`../casey/docs/plans/entity-ui-wiring/evidence/realmachine-spike-findings.md`，本树同路径亦有副本）探明了通道事实：

- 平台 `agentId`（19 位纯数字）与 `agentCode` 只在列表接口 `queryAgentPageList` 的网络信封里；
- DOM 卡片（`article.agent-card`）只有名称（标题）与编码（副标题），无 ID 属性；
- 搜索参数 `nameLike` 名称编码一参通吃。

没有信封门，同名智能体被分页/滚动藏住时 DOM 唯一性门会误判唯一——这正是「同名绝不取 first」需求在真机上的残余风险面。

## 为什么现在做

上游全就绪：`agent.searchOpen` 输入侧已收口（`exact:true`+容器归属闸+`code` 参数）、回放取证层有逐步归因 `requestLog` 基建、身份收据内核有 `code`/`platformId` 字段位、今晨真机签署留了「code 待真机回读」显式待办标记等兑现。

## 入口分流

碰 `lib/`（判别门、编译、回放、sign）+ 夹具 + 金牌 + 收据面，全链新验收：full；并行轨 worktree（护栏 #18，主树另有未提交增量）。

## 四分岔（Steven 2026-07-22 拍板）

1. **D1 消费口径 = DOM+信封双证**：DOM 唯一性门照旧；另加信封门——名称命中行必须恰一（给了 `code` 则名+码同时中）；信封同名多行即使 DOM 只显一条也判 `AMBIGUOUS`（抓分页藏同名）。
2. **D2 降级序 = 剖面声明制**：`profile` 声明 ID 通道（`agents.listApi`）则信封门必跳必过、捕不到即硬阻断；未声明维持现行 DOM 门（存量金牌零回归）。不做「有则用无则降」——真机捕获失败不得静默丢 ID 防线。
3. **D3 收据面 = 一步到位**：编译执行段落身份观察（读回三元组）；sign 收据面新增观察对账——收据（`kind:agent`）携的 `name`/`code`/`platformId` 必须与观察三元组一致，不一致拒签。收据来源语义不变（既有对象仍 `existing`+`user-confirmed`，人确认、机对账）。
4. **D4 真机面 = 只读实证脚本**：真机搜索后用新门纯函数对活数据跑判别、证据入契约；完整真机用例链（含签署消费）route:human。

## 风险与守点

- 信封捕获的数据最小化：只留声明路由响应里的 (id, code, name) 三元组投影，不留完整响应体（护栏 #7 面）；字段名可由剖面覆写、缺省按尖峰实测。
- 归因窗口：搜索请求发生在 fill/Enter 步，点击门消费的是「本 intent 内已归因的最近一次列表响应」——跨 intent 不得串用，无归因响应=捕获失败=硬阻断（D2）。
- 存量零回归：未声明剖面的一切既有金牌（searchopen 四金牌、chat 冒烟等）行为字节不变；新门只在声明剖面后开。
- sign 面向后兼容：无观察件时收据对账门不激活（既有 lockchain 金牌零回归）；有观察件而收据不一致=拒签 65。
- 评审纪律：plan 前提送 sol max（策略/前提异构评审），实现后 codex 评（家族≠实现家族）。
