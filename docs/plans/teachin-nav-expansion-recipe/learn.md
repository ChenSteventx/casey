## 一、修了什么

真机侧栏「组展开+条目」两击导航无配方致自动闭环必转人工——`BUILTIN_RECIPES`
增带槽双击配方 + `matchesAt` 槽位校验 + `boundIntents` 防合并守卫 + 末槽语义绑定 +
`resolved-projection` 交集接线。真机实证：新采两击语料 `teachin-plan` exit 0
（计划层真通）；闭环全链停在下一层 `RUN_COMPLETION_INVALID`（活体源回放执行，
新接缝、后继契约）。

## 二、教训

1. **「松匹配+下游兜底」的兜底论证要跑到下游尽头**：初版赌闭环等价性兜住吸收
   风险，codex 把「expected 空断言+双回放不比动作序列」的假绿路实锤——兜底不
   存在。凡「X 会兜住」的论证，先证 X 真的在比对那个维度。
2. **`ruleId` 这类弱标识做语义查找=劫持面**：按名 find 首条的地方，注册表同名
   登记即可影子劫持。查重+先到权威是最小修；根修是单元携带精确配方身份。
3. **入参能力校验要防「看似在场实则空转」**：幽灵成员（投影外 seq）、可覆写的
   `Set.has`、缺内部槽的 Proxy——三类都让守卫静默失效。口径：原生原型读取+
   内部副本+存在性核对，且金牌必须**双向钉**（合法者必须放行生效、非法者必须
   拒付），单向宽断言冻不住策略。
4. **负控实测是修复轮的验收器**：本契约七轮评审每轮修复都配「撤修看红在哪」，
   三次逮住断言写松（含 N8 宽断言会放过「拒绝一切子类」的回退）。
5. **纯核心源码文本禁令靠 gate 不靠自觉**：修复注释里写评审方厂商名被
   boundaries B2 当场拦——「先 gate 后汇报」的直接收益。
6. **金牌行数与家族扫描面**：764 行金牌不在 `teachin-replayability-*` 的 600 行
   扫描面内；并家族前先下沉装具（N10 能力铸造链约 90 行）。
