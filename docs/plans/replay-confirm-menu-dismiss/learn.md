## 一、注释里承认假绿，不等于修了假绿

上一轮我在夹具 `click()` 与 R26–R28 上方写了「R12 因此是假绿」，自认为已经处置。异构评审
（grok）直接指出：R12 本身**一个字节没动**，仍在不建模遮挡的夹具上断言确认成功。

这条值得单独记住，因为它的错法很隐蔽——写下「这里有个假绿」会让人（包括我自己）产生已经
处理完的错觉，而读者拿到的仍是一条会在真机上说谎的断言。**注释是给人看的，断言是给机器
判的；只改注释等于只安慰了人、没改变机器的结论。**

处置的正确形状：把断言收窄到它真正证得住的命题，把它证不了的部分明确交给别的检查。收窄之后
**必须再验它不是空检查**——我用突变 `DIALOG_SELECTOR`（让菜单被当成弹层）确认 R12 仍会真红。
不做这一步，就等于用一个无害的空壳换掉一个假绿，账面上还更好看。

## 二、红先行签名要分「字段红」与「功能红」，两者不可互相替代

原红基线三条签名全是「字段 `undefined`」——它钉的是「加法字段在场」，不是「确认真的被拦」。
grok 判这条为「红基线偏字段」，判得准：一个只钉字段在场的红基线，会被「字段齐全但根本没真等」
的实现骗过去。

补上的突变三正是那种实现：`menuDismiss: { dismissed: true, waitedMs: 0 }`——证据字段齐全、
自称已离场，但因为没真等，R26 的确认落笔实测 `action_failed`。这才是功能红。

**下次立契约时，红先行基线要同时给出两种签名**：字段红（形状层）与功能红（行为层）。
只有形状层的红基线，护不住「伪造证据」这一类实现。

## 三、跑批期间的环境故障会伪装成回归，退出码不足以分辨

本轮第一次跑受影响金牌，第 21 份起连续 30 份全 `exit 1`，其中包括我自己刚跑过 28/28、
两路评审也各自独立跑过 28/28 的 `wf-delete-card-layout`。根因是 `/mnt/d` 的 9p 静默断连
（看门狗约 30 秒后自愈）。

如果只看退出码，我会得出「本刀引入 30 份回归」的彻底错误结论，并可能据此回滚一个正确的修复。

项目已有的纪律是「判金牌只信退出码」（防的是 grep 失败标记串误判）。这条仍然对，但要补一个
前提：**退出码只在跑批本身健康时才是权威**。跑批脚本此后一律：

- 逐份 `2>"$ERRDIR/$base.err"`；非零退出先 `grep -qiE 'EIO|i/o error|ENOENT|no such file'`
  分流成 `INVALID_IO`（作废待重跑）而不是 `RED`；
- 跑批前用读风暴探针（连读全部目标文件两三轮）确认盘稳；
- 见「大段连续红且其中含确证绿的项」，第一假设是环境故障，不是回归。

同理，hook 报 `LOCK_MISMATCH` 或包文件不可读时，别急着判包损坏——本轮与已知好副本
`diff -rq` 零差异，包完好，是瞬时 I/O 抖动。

## 四、自己写的数字要按可重跑规则复算，别凭印象记账

提交 `630958d` 的信息里写「串行复跑 32 份，7 份红」。两个数都是错的，而且当时没落清单。
grok 查出 plan/accept 里都没有那 7 份路径、无从独立核对，判 `NEEDS_HUMAN`——判得对。

定死一条**可重跑的选集规则**后复跑，真实是 50 份 / 49 绿 / 1 红。先前那 7 份「红」不可复现，
最可能就是第三条说的掉盘假红。

教训不在「数错了」，而在**当时没有把选集规则写下来**。规则没落档，数字就无法复算，也就无法
被任何人（包括我自己）证伪。此后凡在交付物里写「复跑 N 份、M 份红」，必须同时落下能重跑出
这个 N 的选集命令与逐份退出码。

## 五、评审环境的接包姿势会造出整片假红，且两路会同时报同一条

两路评审都报「`selftest --tier1` 有红」。差点被我当成既有陈旧红收下。实测：同一哈希下实现
工作树全绿、评审克隆树 exit 1。根因是克隆树把 loop-kit 接成**软链**兄弟目录，包定位不接受
软链，shim 降级矩阵对 lint 类返 0，于是「黑名单方向」那条（期望 exit 1）判红。换成真目录
副本后五项全绿。取证见 `evidence/tier1-clone-degrade-artifact.md`。

两个独立评审方同报一条，很容易被当成强证据。**但「两路同报」只说明他们环境相同，不说明结论
对。** 判据仍是自己在实现树上复现，以及找出两处环境的差异项。

顺带一个正面发现：降级态下 tier1 第 1 项（`term-lint --registry`，期望 exit 0）会被降级值
蒙成假绿，真正逮住降级的是第 2 项黑名单方向（期望 exit 1）。**正向检查与降级值同号时会被
降级蒙蔽，反向检查不会**——tier1 保留双向是对的，这条对以后设计自检项有普适价值。

## 六、突变还原用备份文件，绝不用 git checkout

本轮早先踩过一次：实现还没提交就用 `git checkout -- <file>` 还原突变，把刚写的实现整段抹掉，
只能重写。此后一律 `cp` 到 scratchpad 备份、每轮突变后 `cp` 回来、最后核 sha256 逐字节相同。
本契约后续三次突变（判据反转、伪造证据、污染弹层选择器）全部按此执行，三次还原哈希均一致。
